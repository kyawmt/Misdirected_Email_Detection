It reads aggregate fields only: of the frozen test record it reads an explicit list of counts and intervals (see [Records read](#records-read)) and never a per-draft outcome, a draft id, or a subject.

Served bundle: contract `med-api-v1`, snapshot `med-synth-v4`, features `med-features-v2`, model `med-model-v2` (`logistic_all_balanced`), policy `med-policy-v2`, `T_warn = 0.9996767050340489`, blocking disabled. Scores are uncalibrated risk scores, not probabilities. All data is fictional, on reserved `.example` domains. Everything here describes a simulation on synthetic data. It does not show real-world detection accuracy, a confidence-supported warning budget, or production readiness, and it does not show that detection improved over any earlier version.

### Measured values and decision rules

**AC01 — Interruption budget: insufficient evidence.** 0 / 5,970 legitimate `test_product_like` emails warned (0.00 per 1,000; warnings 9, blocks 0, coverage 100.0%). The exact 95% upper bound, 0.62 per 1,000, holds only if emails are independent, and independence is not established: most test drafts come from one sender. *Rule:* not met if the point estimate on `test_product_like` is above 1 per 1,000; met only if the exact upper bound is within the budget and emails can be treated as independent; otherwise insufficient evidence. ## 6. Demonstrated versus assumed

### Demonstrated on this simulation (measured, with denominators)

- At the frozen cutoff on the one product-like test pass: 9 / 30 mistakes warned and 0 / 5,970 legitimate emails warned (section 1).
- Which scenarios the policy catches, partly catches, and never warns on, including three it never warns on (section 2).
- Which model and which features were selected, from validation only, and what the content features add on this generator (section 3).
- Warm latency on one machine, with the boundary of each measurement and one probe above the target (section 4).
- Failures fail closed: 9 altered bundles refused, 4 failing rollback candidates, and 5 failure fixtures, each with no decision and no score.
- A local rollback was rehearsed in 2 ways (container and process): 2 of 2 passed, and the known-good deployable was restored and re-verified against 20 recorded fixtures each time.

### Assumed, or not established

- **Prevalence.** 0.5% misdirected product-like mail is a simulation assumption. The training subset is enriched to 10.0% and is not an operating point. Real prevalence is unknown.
- **Independence.** Emails are not shown to be independent draws: most test drafts come from one sender. AC01 stays **insufficient evidence** for this reason, and every exact interval above is conditional on independence.
- **Fictional data.** Labels are stipulations (17598 recipient labels), the people and addresses are fictional, and the generator wrote the scenarios, so results depend on its assumptions.
- **Few positives.** 20 and 30 misdirected emails in the two product-like subsets; recall estimates are coarse.
- **Calibration.** `calibration: not_fit`. Scores rank risk; they are not probabilities.
- **One machine.** Latency and the container checks ran on one arm64 machine and one container runtime (Docker Desktop). One other CPU architecture was checked (linux/amd64, emulated): 20 of 20 fixtures passed.
- **No real users or reviewers.** Reviewed labels on the monitored traffic: 0. The review in the monitoring replay is `simulated reviewer: the stipulated label of each queued validation draft, returned after a seeded delay`; feedback changed 0 labels and left the policy and model unchanged (yes). Monitoring thresholds are conventions no real incident has tested.
- **Not verified when the Phase 9 record was written.** GitHub Actions itself: the workflow file was not executed by a GitHub runner from this machine. Later status: [CI on GitHub](LIMITATIONS_AND_FUTURE_WORK.md#ci-on-github).
- **Not tested.** No Linux host and no Windows host was used, nothing was pushed to a registry or hosted, and there is no shadow mode, canary, or live rollback switch. See [limitations and future work](LIMITATIONS_AND_FUTURE_WORK.md).
